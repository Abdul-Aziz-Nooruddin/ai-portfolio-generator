# 🏛️ Phase 43 — Project Form Causality

## 1. Evidence-Driven Project Presentation

Project presentation forms are selected based on the specific evidence payload of each project artifact:

| Available Project Evidence | Selected Project Form | Visual Justification |
|---|---|---|
| Conference paper, DOI, Abstract | `academic-research-paper` | LaTeX-style academic block, citation links |
| Architecture diagram + Metrics | `technical-dossier` | System topology blueprint, trade-off table |
| Verified quantitative KPIs | `compact-metrics-table` | Telemetry grid with high-contrast benchmark metrics |
| 3D shaders, WebGL, Visual media | `asymmetric-media-mosaic` | Fluid media aspect ratios, viewport spotlight |
| Problem, Solution, Tech Stack | `case-study-narrative` | Structured multi-column essay with callout sidebar |
| Minimal script (<80 chars desc) | `typographic-index-reveal` | Clean numbered list with hover reveal |

---

## 2. Invariant: Form Follows Artifact
The generator does not mechanically assign `project[0] -> hero`, `project[1] -> terminal`, `project[2] -> magazine`. Every project receives a layout justified by its own internal evidence depth.
