# 🏛️ Phase 45 Zero-Loss Architectural Contract

## Core Philosophy & Invariant
> **"DESIGN MAY CONTROL HOW INFORMATION IS PRESENTED. DESIGN MUST NEVER CONTROL WHETHER USER INFORMATION EXISTS."**

The Zero-Loss Evidence Architecture formalizes architectural boundaries across the entire generative pipeline to ensure that no fact, claim, link, image, or custom field provided by the user is ever silently dropped, truncated away, or replaced by generative hallucinations.

---

## 1. Architectural Retention Statuses

The contract defines four distinct retention lifecycle states:

```javascript
const EVIDENCE_RETENTION_STATUS = {
  PRESERVED_PRIMARY: 'PRESERVED_PRIMARY',       // Rendered in primary visual section (Hero, Featured Case Study)
  PRESERVED_CONTEXTUAL: 'PRESERVED_CONTEXTUAL', // Rendered in secondary flow (Sidebar Rail, Timeline Node, Metadata Pill)
  PRESERVED_APPENDIX: 'PRESERVED_APPENDIX',     // Rendered in structured Additional Evidence Appendix
  DROPPED_VIOLATION: 'DROPPED_VIOLATION'        // Fatal violation: field failed to reach DOM
};
```

---

## 2. Provenance Tiers

When multi-source data is provided, facts are categorized and preserved according to verification confidence:

1. **`TIER_1_VERIFIED`**: Cryptographically or API-verified facts (GitHub commit trees, repository topics, star counts, official DOI publications).
2. **`TIER_2_USER_EXPLICIT`**: Directly uploaded resumes, PDFs, questionnaire responses, manual form submissions, and explicit custom field extensions.
3. **`TIER_3_INFERRED`**: Layout pairings and aesthetic tokens generated by design intelligence (must NEVER overwrite Tier 1 or Tier 2 facts).

---

## 3. The Fallback Invariant

If an active design grammar or spatial topology does not have a dedicated primary component slot for an arbitrary user-supplied field (such as `patentsHeld`, `cveDisclosures`, `grantFunding`, or `hardwareRobotsSupported`), the system **MUST NOT** discard the field.

Instead, the execution pipeline automatically routes the item to `AdditionalEvidenceSection`, which uses `EvidenceFallbackRenderer` to render the specification with grammar-coherent styling into the DOM.
