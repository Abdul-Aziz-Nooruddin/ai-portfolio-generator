# 🏛️ Phase 32: Input Source & Multi-Modal Ingestion Architecture

## 1. Overview

Users can create their portfolio using any single source or any combination of sources.

| Source Option | Supported Input Format | Size & Format Limits | Validation Method | Data Provenance Level |
| :--- | :--- | :--- | :--- | :--- |
| **Option A: GitHub** | Username, `@handle`, `https://github.com/user` | Public account | Regex validation + GitHub API verification | `VERIFIED` |
| **Option B: Resume (PDF)** | `.pdf` file payload | $\le 10$ MB, $\le 5$ pages | Magic-byte check `%PDF-` + page count parsing | `USER_PROVIDED` |
| **Option C: Visual Material** | `.jpg`, `.png`, `.webp` (up to 3 files) | $\le 5$ MB per image | Magic bytes (`0xFFD8FF`, `0x89PNG`, `RIFF...WEBP`) | `USER_PROVIDED` |
| **Option D: Guided Questions** | Form fields (Name, Role, Project, Skills, Objective) | 5 structured questions | Length and required field validation | `USER_PROVIDED` |
| **Option E: Combined Mode** | Merged payload across all active sources | Unlimited combination | Conflict resolution matrix | Mixed (`USER_PROVIDED` > `VERIFIED` > `INFERRED`) |

## 2. Provenance Tracking Engine

In `UnifiedProfileNormalizer`, every profile attribute records:
```json
{
  "name": "Elena Rostova",
  "provenance": {
    "name": { "source": "questionnaire", "level": "USER_PROVIDED", "confidence": 0.98, "timestamp": 1740000000 },
    "projects": { "source": "github", "level": "VERIFIED", "confidence": 0.90, "timestamp": 1740000000 },
    "role": { "source": "resume", "level": "USER_PROVIDED", "confidence": 0.95, "timestamp": 1740000000 }
  }
}
```

### Conflict Resolution Strategy
1. `USER_PROVIDED` inputs explicitly typed or selected by the user take first priority.
2. `VERIFIED` facts directly pulled from public APIs take second priority.
3. `INFERRED` facts generated by Design Intelligence fill in remaining optional slots and are never presented as verified historical claims.
